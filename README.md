# Midscene Android 案例执行

本地网页控制台：用自然语言写下测试案例，由大模型拆成操作和断言，再通过 adb 让 Midscene 在 Android 手机上执行，并生成带过程截图的 HTML 报告。

## 准备

1. 安装 [adb](https://developer.android.com/tools/adb)，手机打开 USB 调试，执行 `adb devices` 能看到设备。
2. 复制环境变量并填入模型接口（拿到接口后再填即可）：

```bash
cp .env.example .env
```

- `PLANNER_MODEL_*`：把自然语言拆成步骤（纯文本）。例如 **LongCat** 只填这里即可。
- `MIDSCENE_MODEL_*`：手机上看屏、点按、断言，必须是 [Midscene 支持的视觉模型](https://midscenejs.com/model-common-config.html)（豆包 Seed、Qwen3、Gemini 等）。**LongCat 不能用于 Midscene**（接口不支持截图请求）。
- 规划模型留空时会复用 `MIDSCENE_MODEL_*`。报告结论由本地生成，不再调模型。
- 规划接口按 `POST {BASE_URL}/chat/completions`（Planner 的 Base URL 需带 `/v1`）。

3. 安装并启动：

```bash
npm install
npm run dev
```

打开 http://127.0.0.1:3920 。

不想自己敲终端命令时：在 Finder 里双击项目里的 **`启动控制台.command`**（首次可能要在「系统设置 → 隐私与安全性」里允许运行）。会打开一个窗口跑服务，**不要关那个窗口**；关掉就等于停服务。

修改 `.env` 后，在控制台点 **「重新加载配置」** 即可，不必刷新页面或重启终端。

## 用法

1. 刷新并选中手机。
2. 在文本框写入步骤和期望，例如：「打开设置，进入 WLAN。确认页面上能看到 WLAN 开关。」多个案例之间用单独一行的 `---` 分开。
3. 点「理解并保存」。模型会把原文拆成 `action`（交给 `aiAct`）和 `assert`（交给 `aiAssert`）。
4. 「执行选中的一条」或「批量执行勾选」。同一时间只跑一个任务，批量按顺序执行；除第一条外，后续案例默认不再冷启动 App。若后一条要接在上一条结束界面继续，在案例「编辑」里为对应步骤勾选 **接续跳过**（仅批量且本条不是第一条时跳过该步）。单独执行该案例时仍逐步执行。
5. 断言或操作失败会停下该案例的后续步骤，并继续下一个案例。
6. 结束后打开测试报告，查看每步截图和结论。

若包名能被模型识别出来，执行前会用 `adb shell monkey` 拉起应用。

## 预留的大模型思考点

| 位置 | 作用 |
| --- | --- |
| `src/llm.ts` | 统一读取配置并调用聊天接口 |
| `src/cases.ts` `planNaturalLanguage` | 自然语言 → 操作 / 断言（含自动补断言）。结果写入案例文件，重复执行不会再次调用 |

拆解时会把同一屏的连续操作合成一条 `action`，把同一屏的检查合成一条 `assert`，从而减少 Midscene 看屏幕的次数。若你只写了「点进某频道」这类操作、没写期望，规划模型会在进入后自动补上「已到目标页、界面展示正常」类断言。只有改了原文才需要点「重新理解」。

模型未配置时，案例仍会按原文保存，页面会提示稍后再理解；手机执行需要 Midscene 的模型配置。
